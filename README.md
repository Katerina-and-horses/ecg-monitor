# ECG Monitor — техническая документация

Одноканальный регистратор ЭКГ для лошади и человека: ESP32 + AD8232 + microSD, отображение на телефоне через Wi-Fi.
Документ описывает прошивку `ecg_monitor.ino` (v3.0) из этого репозитория. История разработки и принятые решения — в `PROJECT_NOTES.md`, схемы наложения электродов — в `ЭКГ_лошадь_расположение_электродов.pdf`.

> **Регистратор не является медицинским изделием.** Он предназначен для скрининга и учебных целей; заключение по записи даёт ветеринарный врач.

## 1. Назначение и характеристики

Прибор снимает одно отведение ЭКГ, показывает кривую и ЧСС в браузере телефона в реальном времени и одновременно пишет сырой сигнал на карту памяти. Запись на карту не зависит от связи с телефоном: телефон служит пультом управления и библиотекой копий.

| Параметр | Значение |
|---|---|
| Число отведений | 1 (электроды IN+, IN−, RLD) |
| Аналоговый тракт | модуль AD8232: инструментальный усилитель, фильтры, активное подавление синфазной помехи (RLD) |
| Полоса пропускания | ≈ 0,5–40 Гц (задаётся модулем) |
| Усиление | фиксированное, ≈ 1100 (на типовых модулях AD8232); программно не регулируется |
| АЦП | встроенный АЦП ESP32, 12 бит (0–4095), аттенюатор 11 дБ, вход GPIO34 (ADC1) |
| Частота дискретизации | 250 Гц, аппаратный таймер |
| Контроль отрыва электродов | выходы LO+ / LO− модуля AD8232 |
| Хранение | microSD (SPI), бинарный файл на сессию, выгрузка в CSV |
| Связь | собственная точка доступа Wi-Fi, HTTP (порт 80) и WebSocket (порт 81) |
| Отображение | браузер телефона, без установки приложений |
| Режимы | «человек» / «лошадь» (разные пороги подсчёта ЧСС) |

## 2. Комплектующие

| Компонент | Примечание |
|---|---|
| Плата ESP32 DevKit (модуль WROOM-32) | USB-UART обычно CH340, на ПК определяется как `USB-SERIAL CH340` |
| Модуль AD8232 с 3-проводным кабелем (3,5 мм) | цвета: красный, жёлтый, зелёный |
| Модуль microSD (SPI) и карта microSD, FAT32 | модуль с регулятором напряжения можно питать от 5 В |
| Электроды | тканевые кольцевые на эластичном ремне (подпружный ремень + петля через холку) |
| Питание | повербанк или аккумулятор с USB (см. [раздел 12](#12-электробезопасность)) |
| Проводящая среда | ЭКГ-гель, при отсутствии — физраствор или вода |

## 3. Схема подключения

```
AD8232              ESP32 DevKit
  OUTPUT  ───────►  GPIO34  (ADC1; ADC2 нельзя — он занят Wi-Fi)
  LO+     ───────►  GPIO26
  LO−     ───────►  GPIO25
  SDN     ─ не подключён (модуль всегда активен)
  3.3V    ───────►  3V3
  GND     ───────►  GND

microSD (SPI)       ESP32 DevKit
  CS      ───────►  GPIO5
  MOSI    ───────►  GPIO23
  MISO    ───────►  GPIO19
  SCK     ───────►  GPIO18
  VCC     ───────►  3V3 (или 5V, если на модуле есть регулятор — см. маркировку)
  GND     ───────►  GND
```

Пины одинаковы во всех версиях прошивки, менять их не нужно.

## 4. Сборка и прошивка

**Зависимости**

- ядро ESP32 для Arduino **3.x** (проверено 3.3.8). На ядре 2.x прошивка не соберётся: используется новый API таймера `timerBegin(freq)` / `timerAlarm(...)`;
- библиотеки: `ArduinoJson` 7.x (проверено 7.4.3) и `WebSockets` Markus Sattler 2.x (проверено 2.7.2);
- `WiFi`, `WebServer`, `DNSServer`, `SD`, `SPI`, `FS` входят в ядро.

**Важно:** Arduino компилирует все `.ino` в папке скетча как один файл, поэтому в папке должен быть только `ecg_monitor.ino` (старые версии — в `old_versions/`). Имя папки скетча должно совпадать с именем файла: клонируйте репозиторий в папку `ecg_monitor`.

**arduino-cli**

```sh
git clone https://github.com/Katerina-and-horses/ecg-monitor.git ecg_monitor
arduino-cli core install esp32:esp32@3.3.8
arduino-cli lib install ArduinoJson@7.4.3 WebSockets@2.7.2
arduino-cli compile --fqbn esp32:esp32:esp32 ecg_monitor
arduino-cli upload  --fqbn esp32:esp32:esp32 -p COM7 ecg_monitor   # порт может отличаться
```

Ожидаемый размер: ≈ 1,09 МБ (83 %) флеш-памяти, 56 КБ (17 %) ОЗУ.

**Проверка запуска** — монитор порта на 115200 бод. Нормальный лог:

```
=== ECG Monitor v3 Boot ===
[SD] Инициализирована
[WiFi] AP: ECG_Monitor  IP: 192.168.4.1
[HTTP] Запущен на порту 80
[WS]   Запущен на порту 81
[SD]   Задача записи запущена на ядре 0
[ADC]  Таймер 250 Гц запущен
=== Готово! http://192.168.4.1 ===
```

Без карты памяти вместо второй строки будет `[SD] ОШИБКА инициализации SD-карты! Запись работать не будет.` — прибор продолжит работу (живой монитор работает, запись нет) и не уходит в перезагрузку.

## 5. Работа с прибором

1. Вставить карту памяти, включить питание.
2. На телефоне подключиться к сети **`ECG_Monitor`**, пароль **`ecg12345`**. Если телефон предупредит, что в сети нет интернета, — остаться подключённым.
3. Открыть в браузере **`http://192.168.4.1`** (на Android часто открывается сама). На заставке — напоминание о раскладке электродов, кнопка «НАЧАТЬ».
4. Наложить электроды ([раздел 6](#6-электроды)) и дождаться индикатора «сигнал OK».
5. Кнопкой режима выбрать человека или лошадь. Кнопка показывает режим, **в который** произойдёт переключение: надпись «🐴 ЛОШАДЬ» означает, что сейчас включён режим «человек».
6. Выбрать профиль (животное/пациент) или создать новый.
7. «⬤ ЗАПИСЬ» — начать запись на карту; «⚑ МЕТКА» — поставить метку события (начало движения, испуг и т. п.); повторное нажатие на кнопку записи — остановить.
8. Вкладка «📁 БИБЛИОТЕКА»: записи сгруппированы по профилям; «выгрузить на телефон» скачивает CSV и сохраняет копию в памяти браузера (IndexedDB). Можно открыть до трёх записей одновременно для сравнения — показываются кривые и сводка: ЧСС, разброс интервалов RR, число пиков, длительность, число меток.

Слайдер «УСИЛ» (1–20×) меняет только масштаб кривой на экране; на запись он не влияет.

Записи с карты памяти **программно не удаляются** (осознанное решение) — карта служит первичным архивом.

## 6. Электроды

| Цвет | Роль | Человек | Лошадь, вариант 2 (основной) |
|---|---|---|---|
| 🔴 красный | IN− | правая рука (RA) | левая сторона холки |
| 🟡 жёлтый | IN+ | левая рука (LA) | левая грудная стенка сразу за локтем (область верхушечного толчка) |
| 🟢 зелёный | RLD | правая нога (RL) | верх плеча слева или мечевидный отросток |

- Зелёный электрод — **активный подавитель синфазной помехи (RLD), а не земля**. В формировании отведения он не участвует, но его контакт так же важен: при сухом RLD сигнал заливает сетевая помеха 50 Гц. С GND платы и сетевой землёй его не соединять; располагать не ближе ширины ладони от сигнальных электродов.
- Кожу смачивать **локально под каждым кольцом**, включая зелёное (гель, физраствор, вода). Весь ремень не мочить: мокрая ткань шунтирует сигнал между электродами.
- Шерсть не выбривать.
- Остальные варианты для лошади: 1 — поперечное (локоть ↔ локоть), 3 — классическое base-apex (правый яремный жёлоб ↔ левый локоть, эталон формы комплексов), 4 — диагональное. Подробно — в PDF.
- При перестановке IN+ и IN− комплексы на экране переворачиваются. Для подсчёта ЧСС это неважно, но для сравнения формы комплексов между записями раскладку нужно соблюдать.

## 7. Архитектура прошивки

```
           ядро 1 (loop)                                   ядро 0
 ┌───────────────────────────────────┐          ┌────────────────────────┐
 │ таймер 250 Гц → analogRead(GPIO34)│          │ sdTask, раз в 1000 мс: │
 │   ├─► adcBuf[10] ──► WS binary     │          │ ring → chunk (≤500)    │
 │   │   (25 пакетов/с, всем клиентам) │          │ chunk → /rec/<id>.dat  │
 │   └─► ring[2000] (если запись)  ───┼─ringMux─►│ flush()                │
 │ HTTP :80, WebSocket :81, DNS :53   │          └────────────────────────┘
 └───────────────────────────────────┘             все обращения к SD — под sdMux
```

- **Карта памяти — источник истины.** Сэмплы при записи попадают в кольцевой буфер в ОЗУ (2000 сэмплов ≈ 8 с запаса), отдельная задача FreeRTOS на ядре 0 раз в секунду сбрасывает их на карту. Поэтому запись продолжается при блокировке телефона, закрытой вкладке и обрыве Wi-Fi.
- **Сетевой стек синхронный** (`WebServer` + `WebSocketsServer`). Асинхронный `ESPAsyncWebServer` пробовали в v1 и отказались как от менее стабильного.
- **Captive portal.** DNS-сервер отвечает адресом прибора на любые имена, а HTTP отвечает на проверочные запросы Android/Windows/iOS (`/generate_204`, `/ncsi.txt`, `/hotspot-detect.html` и др.) страницей-перенаправлением. Без этого Android считает сеть «без интернета» и ограничивает WebSocket — это была одна из причин обрывов связи в ранних версиях.
- **Время.** В сети без интернета и без часов реального времени прибор не знает текущей даты. При подключении телефон присылает своё время (`SET_TIME`), прибор хранит смещение и считает время как `смещение + millis()`. Это время используется только для идентификаторов и отметок начала сессий; время внутри записи задаётся номером сэмпла (точность кварца).
- Доступ к карте из двух ядер защищён мьютексом `sdMux`, к кольцевому буферу — `ringMux`. На время-критичном пути (сэмплирование) мьютекс берётся без ожидания.

## 8. Протокол обмена

### HTTP (порт 80)

| Запрос | Ответ |
|---|---|
| `GET /` | веб-интерфейс (HTML/JS встроен в прошивку) |
| `GET /rec/<id>.csv` | запись сессии в CSV (перекодируется из `.dat` на лету, потоково); 404, если нет |
| проверочные URL captive portal | страница-перенаправление на `http://192.168.4.1/` |
| любой другой URL | то же перенаправление |

### WebSocket (порт 81)

**Живой поток (бинарные кадры, прибор → все клиенты).** 25 кадров/с, по 21 байту:

| Байты | Содержимое |
|---|---|
| 0–19 | 10 сэмплов, `uint16` little-endian, сырое значение АЦП 0–4095 |
| 20 | флаги: бит 0 — отрыв электрода (LO+ или LO−) в момент отправки кадра |

Живой поток идёт всегда, независимо от записи.

**Команды (текстовые кадры JSON, телефон → прибор).**

| Команда | Поля | Ответ |
|---|---|---|
| `SET_TIME` | `t` — время телефона, мс epoch | — |
| `START_REC` | `profile_id`, `mode` (`human`/`horse`) | `{"type":"rec_started","id":…}` или ошибка |
| `STOP_REC` | — | `{"type":"rec_stopped","id":…}`; сессия дописывается в `/index.json` |
| `MARK` | `label` (до 31 символа) | — ; не более 60 меток на сессию |
| `LIST` | — | `{"type":"list","sessions":[…]}` — содержимое `/index.json` |
| `LIST_PROFILES` | — | `{"type":"profiles","profiles":[…]}` |
| `ADD_PROFILE` | `name`, `species` (по умолчанию `horse`) | список профилей — **всем** клиентам |
| `RENAME_PROFILE` | `id`, `name` | — |

Ошибки: `{"type":"error","msg":"…"}` — `bad json`, `already recording`, `not recording`, `sd open failed`.

## 9. Форматы данных

Структура карты памяти:

```
/index.json      список сессий
/profiles.json   список профилей
/rec/<id>.dat    сырой сигнал сессии
```

**`/rec/<id>.dat`** — последовательность `uint16` little-endian, по одному на сэмпл (250 в секунду): биты 0–11 — значение АЦП, бит 15 — отрыв электрода. Идентификатор сессии `id` — время начала в секундах Unix epoch.

**`/index.json`**

```json
[{"id":"1790712345","profile_id":"1790700000000","mode":"horse",
  "start_ms":1790712345123,"duration_s":312.4,"sample_count":78100,
  "marks":[{"i":15000,"label":"шагом"}]}]
```

`marks[].i` — номер сэмпла; время метки = `i / 250` с от начала записи.

**`/profiles.json`** — `[{"id":"…","name":"Кличка","species":"horse"}]`.

**CSV (выгрузка)**

```
# id=1790712345 profile_id=1790700000000 mode=horse fs=250 device=ESP32+AD8232+SD
time_s,raw_adc,lead_off
0.0000,1893,0
0.0040,1897,0
```

`time_s` вычисляется по номеру строки (`n / 250`), `raw_adc` — 0–4095, `lead_off` — 0/1.

**Пересчёт в милливольты (приблизительно).** Прибор не калиброван. Для оценки: выход AD8232 смещён к середине питания (≈ 1,65 В), шкала АЦП ≈ 3,3 В на 4096 отсчётов, усиление ≈ 1100:

```
U_вход(мВ) ≈ (raw_adc − 2048) × 3300 / 4096 / 1100 ≈ (raw_adc − 2048) × 0,00073
```

то есть ≈ 0,73 мкВ на отсчёт. АЦП ESP32 нелинеен у краёв шкалы, а усиление зависит от конкретного модуля, поэтому для амплитудных измерений нужна калибровка по эталонному сигналу. Для анализа ритма и интервалов RR калибровка не нужна.

**Чтение CSV в Python**

```python
import pandas as pd
df = pd.read_csv("1790712345.csv", comment="#")
df["mv"] = (df.raw_adc - df.raw_adc.median()) * 3300 / 4096 / 1100
artifact_share = df.lead_off.mean()
```

## 10. Алгоритмы подсчёта ЧСС и анализа

Выполняются в браузере телефона, прошивка передаёт только сырой сигнал.

**Живая ЧСС.** Изолиния отслеживается экспоненциальным фильтром (α = 0,002). R-зубец фиксируется при превышении порога `max(0,15; 0,6 × максимум)` с рефрактерным периодом **350 мс (человек) / 700 мс (лошадь)**. ЧСС — по среднему интервалу между пиками за последние 10 с (нужно не менее 3 пиков); значения вне диапазона **30–220 (человек) / 20–100 (лошадь)** уд/мин не показываются.

**Анализ записи (библиотека).** Те же пики по всей записи; интервалы RR длиннее 1,5 медианы считаются пропусками. ЧСС — по средней длине остальных интервалов, «HRV» — их стандартное отклонение, мс. В режиме «лошадь» при доле пропусков более 15 % выводится предупреждение о возможной физиологической АВ-блокаде вместо ложной тревоги.

## 11. Известные ограничения

Найдены при разборе кода прошивки (v3.0 из этого репозитория):

1. **Масштаб экрана не откалиброван.** Надпись «25 MM/S · 10 MM/MV» номинальная: развёртка задана в пикселях (200 CSS-пикселей в секунду), и реальная скорость в мм/с зависит от плотности экрана телефона (на типичном смартфоне ближе к 30 мм/с). Амплитуда отображается в относительных единицах, умноженных на слайдер «УСИЛ», а не в мм/мВ. Измерять интервалы по экрану линейкой нельзя — только по CSV.
2. **Режим «лошадь» не считает ЧСС выше ≈ 85 уд/мин.** Рефрактерный период 700 мс ограничивает частоту 86 уд/мин, диапазон показа — 100 уд/мин. Для записей при движении (рысь, восстановление) живой ЧСС верить нельзя; сигнал при этом пишется на карту полностью, ЧСС считается по CSV.
3. **Потеря последней секунды записи.** Задача записи сбрасывает буфер раз в секунду и только пока идёт запись; `STOP_REC` ждёт 50 мс и закрывает файл. Хвост длиной до ≈ 1 с в файл не попадает.
4. **Длительность в индексе может расходиться с файлом.** `sample_count` растёт даже тогда, когда сэмпл не попал в буфер (буфер полон или занят). В нормальной работе это единичные сэмплы, но пропуски в `.dat` не помечаются, и `time_s` в CSV их не учитывает.
5. **Идентификатор сессии без синхронизации времени.** Если запись начата до `SET_TIME` (телефон присылает его сразу при подключении, так что на практике редко), `id` берётся из времени с момента включения и может совпасть с сессией предыдущего включения. Файл при этом открывается на дозапись, и две сессии сольются в один `.dat`.
6. **Детектор ищет только положительные пики.** Если комплекс QRS отрицательный (типично для классического base-apex отведения у лошади), срабатывание приходится на наибольший положительный зубец — обычно T. Частота при этом считается верно, но точка отсчёта RR смещена и зависит от изменчивости зубца T. Для анализа RR по CSV сигнал при необходимости инвертировать.
7. **Живая ЧСС привязана ко времени прихода пакетов на телефон** (`Date.now()`), а не к номерам сэмплов: пакеты по 40 мс плюс задержки Wi-Fi дают погрешность отдельных интервалов в десятки миллисекунд. Для ВСР годится только анализ по записи (по номерам сэмплов).
8. **Отрыв электрода в живом потоке — один флаг на 10 сэмплов** (40 мс), в файле — на каждый сэмпл.
9. **АЦП без калибровки** (`analogRead`, а не `analogReadMilliVolts`), нелинейность у краёв шкалы.
10. **Безопасность сети:** пароль Wi-Fi зашит в прошивку (`ecg12345`), HTTP/WebSocket без авторизации — любой, кто знает пароль, может управлять записью.
11. **Одно отведение и полоса 0,5–40 Гц:** годится для ритма, АВ-блокад, ФП по нерегулярности RR; сегмент ST, точный QT и происхождение сложных экстрасистол надёжно не оцениваются.
12. **Версии на плате и в репозитории могут не совпадать.** На видеозаписях апробации 2026 г. интерфейс отличается от описанного здесь (вкладка «ЗАПИСИ» вместо «БИБЛИОТЕКА», кнопки «CSV» / «СОХРАНИТЬ»). Перед анализом записей стоит уточнить, какая прошивка стоит на приборе, и выложить её в репозиторий.

## 12. Электробезопасность

- Во время записи с наложенными электродами питать прибор **только от аккумулятора или повербанка**. Не подключать плату по USB к компьютеру или зарядному устройству от сети, пока электроды на лошади или человеке: при неисправности сетевого блока питания ток может пойти через электроды.
- Прошивать и отлаживать с ПК — без электродов на живом объекте.
- Кабели закреплять вдоль ремня так, чтобы лошадь не могла за них зацепиться; прибор крепить на ремне в чехле, защищённом от влаги.
- Не применять у пациентов с кардиостимуляторами и в условиях, где нужна сертифицированная аппаратура.

## 13. Диагностика неисправностей

| Симптом | Причина и решение |
|---|---|
| Индикатор отрыва электрода, прямая линия | нет контакта: смочить кожу под каждым кольцом, включая зелёное; проверить разъём кабеля |
| Толстая «пила» по кривой (50 Гц) | сухой или сдвинутый RLD (зелёный); прибор рядом с сетевыми проводами или подключён к сети по USB |
| Плывущая изолиния, всплески | движение лошади, подёргивание кожных мышц, смещение ремня; затянуть ремень, дождаться, пока лошадь успокоится, ставить метку |
| Комплексы перевёрнуты | переставлены IN+ и IN− или электрод сдвинут; для ритма неважно, для сравнения формы — вернуть раскладку |
| ЧСС не показывается или завышена | крупный зубец T превышает порог; неправильный режим человек/лошадь; ЧСС лошади выше 85 (см. [п. 11.2](#11-известные-ограничения)) |
| Связь с телефоном рвётся | остаться подключённым к сети без интернета; отключить мобильные данные на время записи; запись на карту при этом не прерывается |
| «sd open failed», нет записей | карта не вставлена, не FAT32 или неисправна; проверить лог по Serial |
| Страница не открывается | ввести адрес вручную: `http://192.168.4.1` |
